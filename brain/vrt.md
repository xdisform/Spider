# VRT registry — the class-eligibility data the bounty router reads (fix3 B4)

> The single, authoritative registry mapping a vulnerability **class** to its Bugcrowd **VRT** entry —
> `vrt_id` (dotted) + baseline `priority` (P1..P5|varies) + a `cvss_v3_baseline` anchor + `cwe` +
> `default_eligibility`. This file is **data + doctrine the brain and the fleet read** (workflow scripts
> never touch disk, exactly like `brain/modes.md`); recon-2 agents and the synthesizer consult it to tag
> the **eligibility leg** of `objective.mode:bounty`. Adding or refreshing a class is a **data edit**
> (re-run `tools/vrt-sync.py`), never a code one.
>
> This is the eligibility leg of fix3's `mode:bounty` objective, nothing more. It is **not a parallel
> engine**. The F4 wave scheduler and its `requires`/`provides`/`ready`/`unlockScore`, the deterministic
> ORACLE gate, the 4 skeptic lenses, the single-writer synthesizer, and the leash/scope authority are
> **untouched**. Eligibility is a **payout-policy annotation**, never a scope or safeguard change, and it
> **never changes `severity`**.

## What a VRT row is, and the canonical fields it fills (B4 owns these)

Every bug-bounty platform runs the same triple — **(taxonomy class) × (scope/asset eligibility) ×
(CVSS severity)** — and keeps an explicit *not-payable* list. Spider already does CVSS (the synthesizer)
and scope (the leash / `scope.yaml`). This file supplies the missing leg: the **taxonomy class + its
payout-eligibility**, applied *early* so the fleet hunts the P1-P3 payable classes, not P5 noise.

A tagged hypothesis/finding carries exactly these **B4-owned** fields (the canonical field contract,
`brain/schema.md` §Canonical field contract — all OPTIONAL, absent on an impact/flag run):

| field | meaning | owner |
|---|---|---|
| `vrt` | the dotted VRT class id (e.g. `broken_access_control.insecure_direct_object_references_idor`) | B4 |
| `priority` | the VRT **class baseline** `P1..P5\|varies` — **distinct** from `severity` (CVSS/impact band) and from B5 `tier` (evidence-derived reward tier) | B4 |
| `eligibility` | `payable \| excluded \| control-test-only \| unknown` (vs `scope.program` + this registry) | B4 |
| `eligibility_reason` | why (e.g. "matches program.exclusions self-xss", "P5 built-in: missing headers") | B4 |

The `cvss_v3_baseline` column below is the synthesizer's **anchor** vector for the class (the reference
it adjusts up/down with the *proven* evidence). It is **NOT** the per-finding `cvss_vector` — that is
B5's evidence-derived field (`tools/ev-score.py`). The anchor can never raise a finding above its proven
impact; it is a cross-check, both directions (it catches under-grading as well as inflation).

## Where the registry is read (three upstream hooks + two gates — all in the spine)

1. **recon-2 emission** (`workflows/recon-2.mjs`, bounty-gated `eligibilityBlock`): each recon agent maps
   its hypothesis `class` onto a `vrt` id from the map below, sets the baseline `priority`, and marks it
   `excluded` if it matches `scope.program.exclusions` **or** a built-in P5 default — **kept as a lead,
   never dropped** — then ranks payable P1-P3 classes above P4/excluded so the attack phase spends its
   budget where the program pays. Rides the existing `confidence`-ordered ranking; no new ordering engine.
2. **attack pre-schedule** (`workflows/attack.mjs`): the pure `eligibility(h, program)` + the pre-schedule
   partition read the operator's `scope.program.exclusions`/`excluded_classes` (the transcribed list),
   holding an `excluded` + `action:note` class in `ineligible_leads[]` — **never scheduled, never
   dropped**. `control-test-only`/`downrank` stay scheduled. The F4 scheduler, oracle, and lenses are
   untouched; only the *input set* is partitioned, strictly upstream of `ready()`/`unlockScore()`.
3. **synthesizer severity pass** (`brain/synthesis.md`, `.claude/agents/synthesizer.md`): the existing
   "recalibrate by CVSS 3.1 both directions" step takes the class's `cvss_v3_baseline` here as its
   anchor. An `excluded`-class confirmed finding is still written (honest record), flagged
   `eligibility:"excluded"`, and kept out of the submission set. **Eligibility never changes `severity`.**
4. **triage** (`workflows/triage.mjs`, axis #5 ELIGIBILITY) and **report** (`.claude/commands/report.md`):
   an excluded class is dropped to the "Noted, not submitted" appendix unless it chains into a payable
   impact (then the chain's end-impact is what pays — the Bugcrowd combined-impact rule).

The brain seeds the **built-in P5 defaults** below into the effective exclusion set when the operator has
not transcribed them; the operator's `scope.program` always wins. A built-in default only **down-ranks**
(`note` / `control-test-only`), it never hard-drops a lead.

## Mapping doctrine — free-form class -> VRT id (the same idiom as `resolveAttackSkill`)

- **Resolve by keyword**, lower-cased substring, **first-match-wins** — the exact discipline
  `workflows/attack.mjs` `CLASS_ALIASES` / `eligibility()` use (one matching discipline, not two). A
  recon-2 free-form `class` (`jwt-alg-confusion`, `mass-idor`, `cors-reflection-with-credentials`) maps
  to its attack-skill slug, then to the slug's row above.
- **`varies` = the VRT "null"/"Varies" rule.** When a row's baseline is `varies` (IDOR, SSRF, XSS, …)
  the band is **context-dependent**: let the **proven evidence + CVSS** pick it (e.g. IDOR runs P4->P1 by
  the function it exposes). Never pick the band by the tier you *want* to reach.
- **Four honest `eligibility` states** (the closed set):
  - **`payable`** — a genuine payable web taxonomy class with a VRT leaf.
  - **`excluded`** — matches `scope.program.exclusions`/`excluded_classes` or a built-in P5 default.
    Still **in-scope to observe**; simply not pursued/submitted. Kept as a noted lead.
  - **`control-test-only`** — pursue only as a bounded control-test per `policies.*` (e.g. rate-limit).
    This never enables a control-test on its own — `policies.*.enabled` still gates it.
  - **`unknown`** — the honest state for a **surface/technique/CTF class** that is not itself a payable
    web entry (`graphql` surface, `waf-body-bypass`/`interactive-exploit` delivery techniques, the
    post-foothold `internal-recon`/`loot`/`lateral`, the CTF solve classes), **and** for a private
    program whose exclusion list the operator has not transcribed. `unknown` is **pursued but flagged
    "verify eligibility before submit"** — never assumed payable (the same could-not-verify honesty the
    dedup point uses). A surface/technique class pays as the **underlying/delivered class** it proves; a
    post-foothold class pays on the **chain's end-impact**.
- **A P5 class that *chains* into a proven payable impact is paid on the *chain's* impact** (Bugcrowd's
  own rule), never by re-labelling the P5 itself. Feed `eligibility` into the chain-builder so an excluded
  P5 used as a *step* is scored at the chain's end-impact tier.

## Operator overrides (`scope.program`, transcribed like scope — attested, not guessed)

The operator's transcribed `scope.program` (schema in `brain/schema.md`) always overrides this registry:
- **`exclusions[]{match,reason,action,vrt}`** — the program's OWN "won't pay" list. `action` ∈
  `note` (down-rank to a noted lead) | `control-test-only` (bounded control-test only) | `downrank`
  (pursue, but last).
- **`excluded_classes[]`** — known-ineligible classes, same matching discipline.
- **`vrt_overrides[]{match,vrt,priority}`** — per-program mapping/priority overrides (a brief restriction
  or an unusual impact).
- **`min_pursue_priority`** — the **effort floor** (pursue classes at/above this VRT priority; below =>
  note-only). Distinct from `objective.min_payable_tier`, the **submission floor** (B2/owner).
- **`platform_taxonomy`** (`vrt` | `cwe-cvss`) — which vocabulary `/report` emits (Bugcrowd P-ratings vs
  HackerOne CWE+CVSS-environmental).

## The generator — `tools/vrt-sync.py` (generated, never hand-merged)

The map block above is **machine-generated** from a single editorial seed (which shipped attack-skill
slug maps to which VRT dotted id), exactly the "generated, not hand-edited" pattern of
`.claude/skills/index.json` (`tools/skill_index.py`) and `brain/corpus/index.json`
(`tools/corpus_index.py`). Regenerate it with:

```
python tools/vrt-sync.py                               # from the embedded VRT-1.9 reference seed
python tools/vrt-sync.py --vrt-json <pin>/vrt.json --mappings-dir <pin>/mappings   # authoritative refresh
python tools/vrt-sync.py --check                       # lint: is this file's block in sync?
```

Supplying `--vrt-json` overlays the **authoritative** baseline `priority` / `cvss_v3` / `cwe` from a
**pinned local** Bugcrowd VRT checkout (it records that release's `vrt_version` and reports any drift
between the seed and the pin). The tool is **offline** — it fetches nothing; the VRT JSON is a pinned
file the operator checks out. It is deterministic (fixed slug order, no clock, no randomness), stdlib-only,
and carries a `--self-test`. The slug set is asserted in lockstep with `ATTACK_SKILLS` (`attack.mjs`:30)
so the map can never key a class the oracle/skills do not know.

## Backward-compat

A `scope.yaml` with **no `program` block** (the `mode:impact` default) ⇒ `args.program` undefined ⇒
`eligibility()` returns `unknown` with no action, no attack partition (`ineligible_leads` empty), the
`eligibilityBlock` on recon-2/attack is `''` (byte-identical missions), and the `vrt`/`priority`/
`eligibility` hypothesis + finding fields are simply absent. This registry and the schema additions are
**inert data** until a `program` block opts in. The F4 scheduler, oracle, 4 lenses, single-writer
synthesizer, and leash/scope authority are untouched in every path.

## Red line

- **Scope fidelity is sovereign and unchanged.** Eligibility concerns the program's *payout policy*,
  never what is *authorized to test*. It never adds a host, never widens scope, never relaxes a safeguard
  or a leash rule, never enables a control-test (that stays `policies.*.enabled`). An excluded class is
  still in-scope to *observe*; it is simply not *pursued/submitted*, and is **never silently dropped** —
  it is always kept as a noted lead (`ineligible_leads` / the report appendix).
- **Honest classification.** A built-in P5 default only down-ranks; the operator's `scope.program`
  always wins; an un-transcribed private program yields `eligibility:"unknown"` (pursued, flagged
  "verify before submit"), never assumed payable.
- **Evidence-bound severity.** `severity` stays the synthesizer's CVSS+evidence pass; the VRT baseline is
  a cross-check **anchor**, never an override — it cannot raise a finding above its proven impact, and
  `varies` entries are resolved by the evidence/CVSS, not by the desired tier. Never inflate a
  vector/priority/tier to clear a pay floor. **No new capability token** — eligibility is a ranking/
  annotation dimension on hypotheses, never a `requires`/`provides` token, and never gates the scheduler.
